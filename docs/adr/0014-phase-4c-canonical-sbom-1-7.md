# ADR-0014 — Phase 4C canonical CycloneDX 1.7 candidate path

Status: **PROPOSED / REVIEW REQUIRED**

Date: 2026-09-03

## Context

QROS canonical supply-chain policy requires CycloneDX 1.7. Phase 4 Cargo evidence is currently deterministic CycloneDX 1.5 generated by cargo-cyclonedx 0.5.9.

Native cargo-cyclonedx 1.7 support is not available in the accepted release. Upstream PR #875 is still open.

CycloneDX CLI 0.33.1 supports conversion and validation for CycloneDX 1.7, but introducing it as a permanent tool requires an independently locked and reviewed .NET/NuGet supply chain.

## Proposed decision

For a future implementation candidate only:

1. Keep cargo-cyclonedx 0.5.9 as the deterministic Cargo graph extractor while its candidate-only disposition remains valid.
2. Pin CycloneDX CLI source to `b3cfa4b0edc356dad07e0b6e7ab6da0a94af0246`.
3. Pin .NET SDK to `10.0.400` for the candidate tool build.
4. Generate and review a QROS-owned `packages.lock.json` for the exact CycloneDX CLI source revision.
5. Require locked-mode restore.
6. Convert the deterministic CycloneDX 1.5 JSON to 1.7 JSON.
7. Validate against CycloneDX 1.7.
8. Fail closed unless QROS semantic fidelity assertions preserve component/license/hash/dependency evidence.
9. Record exact tool source revisions, tool dependency graph, licenses, build environment and output hashes.

## Non-decisions

This ADR does not authorize:
- implementation
- permanent CycloneDX CLI adoption
- dependency-registry promotion
- main runtime promotion
- packaging
- release
- Yuanta integration
- live trading
- production readiness

## Alternatives

### A. Wait for native cargo-cyclonedx 1.7

Deferred. Preferable if a stable reviewed upstream release arrives before implementation, but not currently available.

### B. Rewrite `specVersion`

Rejected. It proves neither schema compliance nor semantic compatibility.

### C. Use CycloneDX CLI prebuilt release executable

Not selected for the first candidate. It would require a separate artifact checksum/attestation/provenance and execution review.

### D. Use Docker

Rejected for this narrow transformation because it introduces unnecessary tooling/runtime surface.

## Promotion requirements

This ADR may move from PROPOSED only after:
- exact NuGet transitive graph and licenses are known;
- QROS-owned lock evidence is reviewed;
- zero-cost path is confirmed;
- 1.5→1.7 conversion fidelity is demonstrated on the actual Phase 4 SBOM;
- canonical 1.7 output is reproducible;
- no new security or licensing blocker is found.
